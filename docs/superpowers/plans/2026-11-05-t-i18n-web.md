# T-I18N: make `pnpm i18n:check` scan apps/web

**Task:** PAD-138. **Spec:** `docs/superpowers/specs/2026-11-05-launch-ready-checklist.md`, item T-I18N, launch criterion L1.
**Owner:** Engineer A. **Approved by:** CTO, 2026-11-05.

**Acceptance check (from the spec):** CI fails on a deliberately missing web key.

## What exists

- `scripts/check-i18n-keys.mjs` scans `apps/mobile/app` and `apps/mobile/components` only. CI already runs `pnpm i18n:check` (step `i18n keys` in `ci.yml`), so no workflow edit is needed.
- Web's catalog is `apps/web/src/lib/i18n-web.ts`: one `webX` const per namespace, added through 12 exported `registerWeb*Copy(instance)` functions. The shared catalog is `packages/i18n/src/resources/<locale>/<ns>.json`, namespaces `auth`, `common`, `onboarding`. `auth` is in both, merged.
- Web differs from mobile in ways the mobile script can't handle:
  - nested keys: `t('nav.profile')`, `t('errorPage.title')`;
  - namespace prefixes: `t('profile:loadMore')`;
  - aliases, one per namespace, in the same file: `const { t: tc } = useT('common')`. Over 20 files do this;
  - literal messages: `{ ns: 'auth', key: 'password_weak' }`.

## Approach

Add a separate script, `scripts/check-i18n-web-keys.mjs`, and leave the mobile script alone. Run both from `i18n:check`:

```json
"i18n:check": "node scripts/check-i18n-keys.mjs && node --no-warnings scripts/check-i18n-web-keys.mjs"
```

**Read the catalog by running it, don't regex it.** Node 22.18+ strips types natively and `i18n-web.ts` has only an `import type`. Import it, call every export matching `/^registerWeb/` with a fake instance whose `addResourceBundle(locale, ns, res)` records into `ns -> locale -> object` (merging, as i18next does here), then merge the shared JSON. A new namespace is then picked up with no change to the script. A later runtime import in `i18n-web.ts` makes the script fail loudly, which is fine.

**Scan** `apps/web/src` `.ts`/`.tsx`, excluding `*.test.*` and the catalog. Strip block comments, as the mobile script does.

**Per file, bind each translator name to its namespace(s):**
- `{ t } = useT('x')` and `{ t: alias } = useT('x')`; `useT()` with no argument means `common` (the `defaultNS`).
- Same name bound to several namespaces in one file (two components): the key must resolve fully in at least one.
- `t` with no binding in the file (a prop, 32 uses today): the key must resolve fully in at least one namespace of the whole catalog.

**For each literal call, `name('key'`, work out the namespace(s):** a `ns:key` prefix wins, then a `{ ns: 'x' }` option on that call, then the binding. Then:
- the key resolves when it exists as a string in **all three** locales, following dots through nested objects and accepting the plural suffixes (`_zero _one _two _few _many _other`). `fallbackLng: 'en'` would hide a pt-only gap at runtime, and L1 needs all three;
- also check literal `{ ns: 'x', key: 'y' }` messages the same way;
- non-literal arguments are counted and skipped, as on mobile.

**Catalog parity.** Every namespace holds the same flattened key set in all three locales. This is the only thing that covers the 139 dynamic `t(...)` calls against L1, and it's about five lines.

**Guards against a silently empty check:**
- `process.features.typescript` false: exit 1 saying Node 22.18+ is required. `.nvmrc` says `22`, so CI gets the latest 22.x; `engines` stays as is;
- fewer than 1000 literal keys checked: exit 1. Today it's about 1640.

**Output:** keep the mobile script's style: a summary line with counts, then `key - namespace - missing locales`, its files, and where else the key is declared if it's anywhere (that's the actionable half).

**Also:** update the header comment of `check-i18n-keys.mjs` only if it would mislead; say in the spec's L1 line nothing (the PM owns it, tell the CTO when merged).

## Baseline

A CTO prototype (`/tmp/pad138/proto.mjs`, reference only, do not commit) on `origin/main`: 1641 literal uses checked, 139 dynamic, 32 unbound, **0 missing, 0 parity gaps**. So the script should be green on arrival and no catalog edits are expected. If yours reports a real gap, fix the key in all three locales in this PR and list it. If it reports many, your binding logic is probably wrong; the prototype is the comparison.

The prototype caught all of these when added in a probe file: unknown key on `t`, on an alias, nested, `ns:` prefix, `{ ns }` option, and a key that exists only in another namespace.

## Verification

1. `pnpm i18n:check` green on the branch, plus the usual hand-off checks. Nothing under `infra/` changes.
2. Locally, each of these makes `pnpm i18n:check` exit non-zero with the key named, then revert:
   - `t('noSuchKey')` in a web component;
   - the same on an alias: `tc('noSuchKey')`;
   - a key that exists only in another namespace;
   - a nested key: `t('nav.noSuch')`;
   - `t('common:noSuch')` and `t('noSuch', { ns: 'chat' })`;
   - `{ ns: 'auth', key: 'noSuch' }`;
   - a real key removed from pt-BR only, both as a used key and as a parity gap;
   - an empty scan (point the scan at an empty folder): the floor guard fires.
3. **The spec's check, in CI:** push one commit to the PR that uses a missing web key. Link the run with the `i18n keys` step red. Push a revert commit (no force-push) and show it green.
